# JevIntent —— 微信长按「意图」分析插件（v1.4）

长按任意一条消息 → 菜单选 **意图** → 插件调 **TypeSafe Jev**，**结合"关系"和"上下文"** 分析这句话的意图 / 情绪 / 着急程度 / 回复姿态 / 风险。

```
🤖 Jev 意图分析（jev-1.13.0 | 客户·男·3句）
• 意图：催促进度或催回复  66%
• 情绪：着急 100%
• 着急：非常急 · 2.58/3
• 回复：建议正常交流  41%
• 待回复：是  91%
• 风险：无  28%
• 建议：立刻回复并给出明确答复
```

## 〇·〇·五、v1.7：弹出固定 3 条（意图+情绪 / 着急 / 建议）

### 改了什么
v1.6 之前 Toast 是**按字数（42 字）机械切段**的：条数不固定，还可能把一句话从中间切开。
现在**固定 3 条**，分组就是你定的那样：

| 顺序 | 内容 |
|---|---|
| ① | `意图：打招呼或闲聊 85%` ⏎ `情绪：平静 56% · 客套 42% · 着急 2%`（3 个情绪换到第二行） |
| ② | `着急：不着急 · 0.48/3` |
| ③ | `建议：正常交流 90%` |

真机同款路径实测（本地 bsh 跑真 API，`结果方式=A`）：

```text
意图：打招呼或闲聊 85%
情绪：平静 56% · 客套 42% · 着急 2%
着急：不着急 · 0.48/3
建议：正常交流 90%
```

### 连带的三处调整
1. **意图升为核心行**：以前它归「附带老四项」管，关掉就整行消失 —— 现在它固定出现在第一条 Toast 里
   （那个开关现在只管 **待回复 / 风险 / 应对**）
2. **「回复」改名「建议」**，并去掉值自带的"建议"前缀 —— 否则会显示成"建议：建议肯定赞赏"，很别扭
3. **老四项里的「建议」改名「应对」**（跟新的「建议」撞名了）：`应对：立刻回复并给出明确答复`

### 删除 / 新增
- 删：`每条字数` 选项（固定 3 条后没意义了）、按字数切的 `splitToast()` 函数
- 增：`分析中提示`（**A 显示** / B 不显示）—— 分析要 5~10 秒，默认留着「Jev 分析中…」当反馈；
  嫌它多弹一次的改成 **B**，那样就**正好只弹 3 条**

> `结果方式=引用回复/直接发消息` 时发的是一条完整消息（带表头：`🤖 Jev 意图分析（模型 | 关系·性别·N句）`），
> 不受"3 条"限制 —— 那个场景是发文本，不存在被截断的问题。

## 〇·〇·四、v1.6：设置改成 `设置.properties`（A/B/C 选项）

### 为什么换
v1.5 的"文本操作台"（点菜单 → 面板发到会话 → 回命令）在真机上始终打不开，排查到最后是
**bsh 词法器对「中文 + 反斜杠转义」混写的字面量会静默崩掉**（见文末踩坑）。与其在宿主上继续赌，
不如换成**最笨但最稳**的方案：一个设置文件，改字母即可。

### 怎么用
1. 第一次长按消息后，插件目录（和 `main.java` 同目录）会**自动生成 `设置.properties`**
2. 打开它，把想改的那项等号后面的字母改掉，保存
3. **长按消息立即生效**（每次都重读），不用重载插件
4. 这个文件**永远不会被自动覆盖**；删掉它，下次长按会重新生成一份

生成出来长这样（节选，文件里每项都有完整说明）：

```properties
# 【1】情绪条数
#     A. 只显示 1 条
#     B. 显示 3 条
#     C. 显示 5 条
情绪条数=B
```

### 11 个选项一览
| 文件里的项 | 选项 | 说明 |
|---|---|---|
| 情绪条数 | A 1条 / **B 3条** / C 5条 | 情绪显示前几名（比例取自 Jev 的概率分布） |
| 附带老四项 | **A 显示** / B 不显示 | 选 B 就只剩「情绪 / 着急 / 回复」三格 |
| 结果方式 | **A 只弹提示** / B 引用回复 / C 直接发消息 | A = 对方完全看不到 |
| 提示间隔 | **A 2000ms** / B 1200ms / C 3000ms | 三条结果 toast 之间的间隔 |
| 分析中提示 | **A 显示** / B 不显示 | 关掉后正好只弹 3 条（没有"分析中…"那一条） |
| 上下文句数 | A 不带 / **B 3句** / C 5句 / D 7句 | 取目标消息前后各 N 句 |
| 只看文本消息 | **A 是** / B 所有消息都挂菜单 | |
| 引用块字段 | **A title** / B des | 引用气泡空白时改成 B |
| 模型 | **A jev-latest** / B 固定 1.13.0 | |
| 默认关系 | **A 普通朋友** / B 同事 / C 客户 / D 家人 / E 死党 / F 陌生人 / G 领导 / H 同学 | 没单独设过的会话用这个 |
| 默认性别 | **A 未知** / B 男 / C 女 | |

（**加粗** = 默认值）

### 关系还是单独的
关系是"每个会话一个"，放不进全局文件 → 仍在**长按菜单里点「关系＝…」**循环切换，
记在 `presets.properties`（`rel:<会话ID>=关系`）。菜单现在只有两项：**意图 / 关系＝…**。
> 想给某个会话定关系又不想点菜单，也可以直接编辑 `presets.properties` 加一行 `rel:wxid_xxx=客户`。

### 写错字母不会崩
字母认不出来（比如写 `Z`）时，**自动取第一个选项**，并且日志里会写一行，不会让插件失效。

### v1.5 的操作台已废弃
`⚙ 操作台`、`控制台`、`测试点击`、`console_*` 配置项**全部删除**（连 `onMsg` 命令处理也删了，
插件不再挂任何消息钩子，零干扰）。保留的教训写在下面踩坑里。

### 踩坑记录（v1.5→v1.6 这段最有价值）
- **★ bsh 词法器：中文 + 反斜杠转义混写的字面量会静默崩**
  新写的操作台代码里全是 `"中文…\n"` 这种写法。真机表现：点菜单**只弹了 lambda 里第一句内联 toast**，
  之后彻底没声；用"阶梯自检"（D1~D6 每步单独 try）定位到 **停在 D3**（= `consolePanel`）。
  这种死法**不可捕获**（catch 不到、日志不写），跟"宿主缺 API"一模一样。
  **最坑的是本地测试全绿** —— 因为 `mktest.py` 会**自动把这类字面量拆开**，等于掩盖了"只有真机才会犯的错"。
  - 规则：**字面量要么纯中文、要么纯 ASCII+转义；混写必须拆成 `"中文" + "\n"`**
  - `lex_audit.py` 专项扫描（当前 **0 处**）；`mktest.py` 输出的「混合字面量拆分 N 处」当回归指标，
    **必须是 0** —— 不是 0 就说明本地测的不是真机上那份文件
  - 顺手修掉了 13 处**早就存在**的同款（`buildState`、`selfTest`、`cleanForToast`、`savePresets`…）——
    其中 `savePresets` 意味着**关系/性别预设可能从来没在真机上存成功过**
- **命令式 UI 不要在这台宿主上赌**：宿主只有 `toast` 一个 UI 原语（`getTopActivity` 虽然给了 Activity，
  但弹窗+监听器要靠反射，风险更高）。**文件即面板**的方案胜在：零宿主依赖、随时可看、
  不依赖 `onMsg` 是否对自己发的消息触发。

## 〇·〇·二、v1.4：三格定稿（情绪 / 着急 / 回复姿态）

### 为什么要重做
老版「紧急」只有 3 档、没有情绪、没有回复姿态；而且**只取 argmax**，把 Jev 已经算好的
**完整概率分布**扔了。v1.4 把主人定稿的三格接进来：

| 格子 | 问题 ID | 类型 | 选项 |
|---|---|---|---|
| 情绪 | `emotion` | choice ×9 | 平静 / 高兴 / 不满 / 生气 / 焦虑 / 着急 / 难过 / 讽刺 / 客套 |
| 着急 | `urgency` | score 0~3 | 不着急 / 一般 / 急 / 非常急 |
| 回复姿态 | `reply_style` | choice ×11 | 建议调侃打趣 / 建议正常交流 / 建议礼貌客套 / 建议肯定赞赏 / 建议关心问候 / 建议共情吐槽 / 建议表达同情 / 建议先安抚道歉 / 建议先问清细节 / 建议温和婉拒 / 建议暂不回复 |

**情绪比例怎么来的**：`emotion` 是一个 choice，但 Jev 会返回 `probabilities`（全部 9 格的占比），
所以「3 个主情绪 + 比例」直接读分布前 3 名即可 —— **千万不要为了"3 个情绪"开 3 个问题**
（那样只有 3 个 argmax、没有比例、还会互相矛盾）。显示条数由 `emotion_top` 控制。

### 定稿前的实测（`jev_grid_test.py` / `jev_grid_final.py`，20 条样本）
| 指标 | 结果 | 判读 |
|---|---|---|
| 稳定性：情绪 | 20/20 连续 3 次完全一致 | 极稳 |
| 稳定性：回复姿态 | 20/20 | 极稳 |
| 稳定性：着急档位 | 19/20；同句分数极差平均 **0.03** | 极稳 |
| 可分性 | 16/20 = 80%（4 例偏差里 3 例是语义本来就重叠） | 可用 |
| **口径敏感度** | 换一种问法，分数平均漂 **0.46**、最大 **1.25**（0~3） | ⚠ 见下 |
| 空答案率 | 34 次里 1 次（≈3%） | 已加自动重试 |

- **「读不出」被删掉了**：实测 60 次里 0 次被选中，全被「平静」吃掉（合并后 平静 90%/97%/83%，比例更集中）
- **「建议先安抚道歉」这格有用**：实测在「我理亏」「对方催我」的场景会被选中（6 次）
- **⚠ 口径冻结规则**：`urgency` 的 instructions **一旦上线就别再改字** —— 实测换问法等于换量尺，
  改了你之前看到的「着急 1.5」和之后的不可比。情绪/姿态的 instructions 同理。

### 格 3（回复姿态）为什么是 11 格
先铺了 **13 个候选**跑体检（`jev_style_test.py`，25 条样本 × 2 次），结果：

| 观察 | 数据 | 处置 |
|---|---|---|
| 2 个死格 | `建议明确答应`、`建议坚定拒绝` **一次都没被选中** | **砍掉** |
| 谁吃掉了它们 | 该答应的场景 → `正常交流`；该硬拒的场景 → `温和婉拒`/`先问清细节` | — |
| 砍掉的收益 | top1 置信度平均 **0.64 → 0.69**，最低 **0.29 → 0.35** | 更利落 |
| 最终 11 格 | 全部被选中至少 2 次，**无死格** | 定稿 |

实测各格使用频次（25 条样本）：正常交流 10 · 先问清细节 8 · 关心问候 6 · 调侃打趣 4 ·
共情吐槽 4 · 先安抚道歉 4 · 温和婉拒 4 · 礼貌客套 3 · 肯定赞赏 3 · 表达同情 2 · 暂不回复 2

> 注意：格 3 是**姿态建议**，不是回复原文（Jev 不出自由文本）。想直接拿到可发的句子，
> 得再喂一层大模型（见"可扩展"）。

### 配置新增
| 键 | 说明 |
|---|---|
| `emotion_top` | 情绪显示前几名（默认 3），比例低于 1% 的自动不显示 |
| `show_legacy` | 是否附带显示老的「意图/待回复/风险/建议」四项（默认 true；改 false 就是纯三格输出） |

> 附带的老四项**一直在请求里**（多问不额外花钱、也不明显变慢，实测 13 问也照答），
> 只是显示与否由 `show_legacy` 控制 —— 想彻底不问再改 `buildRequest()`。

## 〇·〇、v1.3 修复：**引用消息终于能用「意图」了**

**症状**：对方**引用**某条消息回复（气泡里带引用块）时，长按这条消息 → 菜单里**没有「意图」**。

**原因**：微信里这类消息 `type=49`（appmsg），宿主 `msg.isText()` 返回 **false**。
老代码 `if (cfgBool("text_only") && !isTextMsg(msg))` 把整个菜单跳过了；
而它的 `content` 其实是 XML —— `<title>` 才是回复正文，`<refermsg><content>` 是被引用的原文。

**v1.3 改法**（本地桩宿主 + 真 API 实测通过）：

| 环节 | 老行为 | 新行为 |
|---|---|---|
| 是否挂菜单 | 引用消息 → **不挂** | 能抽出文字就挂（`isTextMsg()` 兜底） |
| 送给 Jev 的正文 | 整段 XML 原文 | `<title>`/`<des>` 抽出的**纯文字** |
| 上下文 | 只有前后对话 | 多一条 `"本消息引用了":"老王：报价单我明天给你"` |
| 图片/语音/视频/表情 | 不挂 | **仍然不挂**（抽不出文字，不误伤） |

实测（引用「报价单我明天给你」并回复「这个记得改一下单价，客户那边催了」）：
```
菜单项数     = 4                                  ← 修好前是 0
msgText()    = 这个记得改一下单价，客户那边催了      ← XML 已剥净
本消息引用了  = 老王：报价单我明天给你
意图：请求帮忙或让我办事 89%｜紧急：很急（马上）｜建议：立刻回复并给出明确答复
```

> 顺带：这条消息的上下文更全了，Jev 的判断也更准（同一句话，引用带来的上下文让它从 80% → 89%）。

## 〇·二、关系真的会改变结论（真 API 实测）
「能借我 5000 块吗？下个月发工资就还你」：

| 关系 | 风险 | 建议 |
|---|---|---|
| 陌生人 | 0.92 | **礼貌婉拒** |
| 普通朋友 | 0.68 | **礼貌婉拒** |
| 同事 | 0.61 | 先问清楚细节再答复 |
| 家人 | 0.49 | 先问清楚细节再答复 |
| 情侣 | 0.47 | 先问清楚细节再答复 |
| 死党 | 0.46 | **立刻回复并给出明确答复** |

「借我10块钱」（金额很小 → 风险应显著降低）：

| 关系 | 风险 | 建议 |
|---|---|---|
| 家人 | **0.25** | 直接答应对方 / 立刻回复 |
| 死党 | **0.18** | 直接答应对方 |
| 同事 | 0.29 | 立刻回复并给出明确答复 |
| 普通朋友 | 0.35 | 礼貌婉拒 |
| 陌生人 | **0.82** | 礼貌婉拒 |

「你把验证码发我一下，我登一下你的号」：陌生人 0.92 → 死党 0.59 → 情侣 0.52，但**所有关系的建议都是「涉及钱/账号，先人工核实再回」**（该硬的地方不会因为关系软掉）。

> 风险问法很关键：早期版本问的是"是否涉及金钱/账号"，导致"家人借 10 块钱"也报 94% 风险。
> 改成问"对『我』的**实际风险**有多大（被骗钱/盗号/隐私/法律/人情）"之后，家人借 10 块 = 0.25（低），陌生人借 10 块 = 0.82（高）。

## 〇·三、上下文怎么取
用宿主 `getMsgs(talker, 时间)` 拉一段窗口（默认 30 分钟），定位到目标消息，取**前 N 句 + 后 N 句**一起送进 Jev 的 `state`：
```json
{"关系":"死党","对方性别":"女","会话类型":"单聊",
 "最近对话":["对方：在吗？","我：嗯嗯，你说","对方：<目标消息>","我：我这边也在等上游"],
 "待分析消息":"…"}
```
`context_count=0` 时**完全不调用** `getMsgs`（重要：bsh 里调用宿主没实现的 API 会不可捕获地炸掉，所以必须让调用点不执行，而不是靠方法内部 return）。

## 一、安装
1. 把整个 `JevIntent` 文件夹拷到手机：
   ```
   /storage/emulated/0/Android/media/com.tencent.mm/FkWeChat/Plugin/JevIntent/
   ```
   目录里要有 `info.prop`、`main.java`、`config.properties`（`README.md`、`test/` 可有可无）。
2. 插件管理器里启用并重载 → 弹 Toast「JevIntent 就绪」。
3. 在任意聊天里**长按一条文本消息** → 菜单里会出现 **意图**。
   > v1.3 起：**引用回复的消息**（气泡带引用块）也能长按出「意图」了；图片/语音/视频/表情仍然没有菜单。

> 当前默认 `reply_mode=toast`：点「意图」后结果以 Toast 弹在屏幕上，**一条消息都不发**，对方完全不知道。
> 实测过某些宿主版本不渲染 `type=57` 引用气泡（点了没反应），所以才默认用 Toast。
> 想看"挂在原句下面"的引用气泡：把 `reply_mode` 改成 `quote`；`quote_text_in` 在 `title`/`des` 之间切换试试。

## 二、配置（`config.properties`）
| 键 | 说明 |
|---|---|
| `api_key` | ⭐ TypeSafe/Jev 的 `apikey_…`（**必须自己填**，仓库里不含任何密钥）。v1.8 起也可以写在 `设置.properties` 的【1】接口密钥里，那边优先 |
| `model` | `jev-latest` 或固定 `jev-1.13.0` |
| `endpoint` | 官方 `https://api.typesafe.ai/v1/systemone`，也可指向**自建中转** |
| `reply_mode` | ⚠ v1.6 起这些开关都搬进了 `设置.properties`（改字母即可）。`toast`=**只在本机弹提示，什么消息都不发（当前默认）**；`quote`=引用回复挂在原句下面；`text`=发普通消息 |
| `toast_gap_ms` | 三条结果 Toast 之间的间隔毫秒，默认 2000 |
| `quote_text_in` | 引用气泡正文放 `title`（默认）还是 `des`（气泡空白就换成 des） |
| `quote_displayname` | 引用块是否带发送者昵称（默认 false，最稳，见第六节第 5 条） |
| `private_mode` | `true`=结果**只发到自己会话**（默认文件传输助手），对方完全看不到 |
| `self_talker` | 私密模式的目标会话，默认 `filehelper`（文件传输助手），也可填自己小号 wxid |
| `whitelist` | 留空=所有会话可用；否则填 talker（wxid），逗号分隔 |
| `show_confidence` | 是否显示置信度/概率 |
| `text_only` | 只给文本消息挂菜单（默认 true） |
| `timeout_ms` | 超时，默认 30s |

改完保存 → 重载插件即可，不用重装。

## 三、实现要点
- **菜单钩子**（官方 doc-8196404 写法）：
  ```java
  onMsgMenu(msg) {
      addMenuItem("意图", "", () -> { analyzeAndSend(pendingMsg); });
  }
  ```
  菜单项在 `onMsgMenu` 里逐次注册，`action` 是**无参 lambda**，所以消息通过脚本级变量 `pendingMsg` 带进去（双保险：同时也做了闭包捕获）。
- **网络**：插件是魔改 BeanShell（Java 脚本）环境，直接用 JDK 的 `HttpURLConnection`，不依赖 loadJar；请求放在 `new Thread(...)` 里，避免卡界面。
- **Jev 是决策模型，不出自由文本**：所以「建议」必须是**预置选项**，用 `type=choice` 让模型挑一个；一次请求里 5 个问题**并行独立评估**：
  - `intent` → choice（10 类意图）
  - `urgency` → score（3 档：不急 / 今天内 / 马上）
  - `need_reply`、`risk` → noul（"是"的概率 0~1）
  - `advice` → choice（8 个应对动作）
- **解析**：不引 JSON 库，`fieldAfter()` 按 `"问题ID":"字段":` 定位取值。

## 五、常见问题：显示「未配置 Jev key」

**v1.1 已经修好了，正常情况下不会再出现。** 新版做了四件事：

1. **多路径探测配置**：`pluginPath` → 硬编码的 Android 路径 → **扫描同级插件目录**（优先挑名字里带 `jev` 的，避免误读别的插件的 config），文件名同时试 `config.properties` / `config.properties.txt` / `config.txt`
2. **自己解析配置**，不依赖 `Properties.load`：自动去掉 UTF-8 BOM、忽略 CRLF、支持 `#` 注释和引号
3. **内置兜底 key**：万一配置确实读不到，插件会直接用源码里的内置 key（日志里会写「配置里没有可用 api_key → 用内置 key」），**照样能用**
4. **长按菜单多了「重载配置」**：改完 `config.properties` 不用重载插件，长按任意消息点一下「重载配置」就生效（会 Toast 出读到的 key 前缀）

### 还是不行？看插件日志
日志里会打印两行诊断，直接把内容发我即可定位：
```
JevIntent ！！没找到 config.properties。试过：<所有试过的路径，✓有 / ✗无>
JevIntent 扫过的目录：<扫过哪些目录、各有多少子项>
```
- `cfgFile` 不为空 → 配置读到了，问题在 `api_key=` 那一行（空值/写错/被空格截断）
- `cfgFile` 为空 → 文件确实不在预期位置：把 `main.java` 和 `config.properties` 一起放进**同一个**插件文件夹
- 常见坑：Windows 复制时文件名变成 `config.properties.txt`（已兼容）；用记事本另存成 UTF-8 带 BOM（已兼容）

## 六、踩过的 bsh 坑（改代码时注意）
1. **无类型 + `final` 解析不了**：`final msgLocal = msg;` 直接让整个脚本解析失败
   → 必须带类型：`final Object msgLocal = msg;`
2. **`try/finally` 里 `return` 会被吞**：方法返回值变成 void（报 `Can't assign void value to java.lang.String`）
   → 所有 return 都挪到 try/finally 外面
3. **解析别只匹配 `"字段"`**：响应里 `"type":"choice"` 会先被撞上，必须匹配 `"字段":`（带冒号）
4. **本地测试要加 `--add-exports`**：JDK17 模块系统不让 bsh 反射 `sun.net.www.protocol.https`（Android 上没这问题，纯本地测试环境限制）
5. **调用宿主不存在的 API = 不可捕获的崩溃**：bsh 里 `getUserRemark(...)` 这种宿主没提供的函数，会抛 `Command not found`，**`try/catch` 抓不住**（它在方法名解析阶段就炸），直接打死线程。所以引用块的 `displayname` 默认不查（`quote_displayname=false`），要查再打开。写这类插件时，任何「文档里有但不确定宿主实现了没」的 API 都要放在开关后面。
6. **stock bsh 2.0b6 解析不了「中文 + 反斜杠转义」的字符串**（v1.3 定位到）：
   ```java
   String s = "{\"关系\":\"普通朋友\"}";      // 中文 + \" → 词法报错 Lexical error
   String s2 = "{\"k\":\"v\"}";               // 纯 ASCII + \" → 没问题
   t.replaceAll("（\\d+）", "");              // 中文 + \\d → 同样报错
   ```
   报错信息很误导（`Encountered: "\\"`，行号可能指向别的方法）。
   **手机上的魔改 bsh 没这个问题**（插件在真机上一直正常跑），
   所以 `mktest.py` 生成测试副本时会**自动把这类字面量拆成 `"中文" + "\\d+" + "中文"` 的拼接**，
   插件源码保持原样、不用为了本地测试改语法。

## 七、上机后仍可能要微调
1. **lambda 支持**：宿主号称魔改 bsh，官方文档示例就是 `() -> {}`。若你的版本报语法错，退回：
   ```java
   addMenuItem("意图", "", this.onIntentMenu);       // 方法引用
   // 或去掉 lambda，改成在 onMsg 里直接判断关键词自动分析
   ```
2. **引用回复**：`reply_mode=quote` 用 `type=57` + `<refermsg>`，正文默认写进 `<title>`。若发出去是空白气泡 → 改 `quote_text_in=des`；若引用块里原消息显示不出来 → 检查 `svrid`（`msg.msgSvrId`）和 `fromusr`（原消息发送者）是否有值。
3. **后台线程发消息**：若宿主要求主线程发消息，用宿主的 UI 线程函数把 `sendResult(...)` 包一层。
4. **`pluginPath`**：读配置依赖这个全局字段，读不到会退回写死路径。
